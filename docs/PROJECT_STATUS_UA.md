# Стан проєкту Kaminchyk

Оновлено: 9 вересня 2026 року. Поточний релізний кандидат: `v1.1.15`.
GitHub потребує публікації цього кандидата; Sites оновлюється окремим кроком.

## Що означає v1.1.15

Це завершений код і production-кандидат продукту, який можна переглядати на
комп’ютері й телефоні. Форма більше не має демонстраційної чернетки: вона або
працює через Turnstile → Worker → D1, або чесно вимкнена через відсутню
конфігурацію. Згенеровані зображення чітко позначені як візуалізації.

Код реальних заявок, Telegram, адмінки, кошторису та конфігурації Cloudflare
готовий і протестований. Для активації потрібні дії власника в зовнішніх
акаунтах: домен, Cloudflare, D1, Turnstile, Access, Telegram secrets і
погоджені юридичні дані. Їх не можна безпечно вигадати або створити від імені
бізнесу.

- доступний мобільний інтерфейс та `prefers-reduced-motion`.

## Готовий production-контур

- `POST /api/v1/leads`: JSON або multipart із вкладеннями до 18 МБ,
  idempotency, валідація, honeypot;
- Cloudflare rate-limit перед Turnstile та обов’язкова server-side перевірка;
- атомарний D1 batch `lead + notification_outbox`;
- Telegram outbox: claim, lease, retry, `retry_after`, `FAILED`, Cron fallback і
  окреме передавання файлів через `sendDocument` лише за явного `true`;
- `/admin`: Cloudflare Access JWT, audience, expiry, email allowlist;
- список заявок, зміна статусу й незмінний audit trail;
- керування видимістю каталогу через admin UI ще не підключене: воно потребує
  runtime D1/Worker-контуру, бо поточний публічний frontend є статичним export;
- окремий серверний калькулятор `InternalEstimate → ClientEstimate`;
- відсутня ціна або правило завжди вимагає ручного уточнення;
- п’ять послідовних D1-міграцій (`0000`–`0004`) й production Wrangler
  example з binding `LEAD_ATTACHMENTS`.

## Production-фото

Контур фото вже реалізований у коді: D1-міграція `0003_magical_warpath.sql`,
приватний R2 для оригіналів, публічний R2 для WebP, Images binding для crop і
конвертації, Access/JWT endpoints в адмінці та публічний endpoint для заміни
статичного fallback після hydration. Нове фото за замовчуванням приховане;
публікація виконується окремим перемикачем.

## Вкладення до заявки

Клієнт може додати до трьох фото-прикладів. Worker приймає лише JPEG, PNG,
WebP або HEIC, до 6 МБ кожне й до 18 МБ разом, перевіряє magic bytes і не
створює публічних URL. `lead_attachments` пов’язує файли із заявкою, а
Cloudflare Access захищає завантаження з адмінки. Telegram отримує текстове
сповіщення та кількість вкладень. За `TELEGRAM_SEND_ATTACHMENTS="true"` Worker
додатково читає ці файли з приватного R2 і надсилає їх у `TELEGRAM_CHAT_ID` як
документи; за замовчуванням прапорець `"false"` і файли залишаються приватними.

## Тимчасове візуальне наповнення

Поточний публічний каталог сфокусований на виробах, які власник попросив
показати першими: столи й лавки, лампадки, вази, точений декор, підвіконня та
стільниці. Пам’ятниковий каталог не видалено, але тимчасово приховано до
окремого погодження асортименту й візуалів.

Коли власник надасть точний список, реальні фото й бізнес-правила, змінюються
дані та assets без руйнування маршрутів і старих заявок. Деталі:
`docs/CONTENT_ASSUMPTIONS_UA.md`.

## Що власник має зробити для реального запуску

1. Погодити домен, адресу/графік і відповідальну особу; бренд уже затверджено.
2. Створити власний Cloudflare-акаунт із 2FA.
3. Купити домен на власника бізнесу й підключити його до Cloudflare.
4. Створити D1, застосувати міграції, Turnstile та Access.
5. Внести Telegram і Turnstile secrets тільки в Cloudflare.
6. Погодити юридичне ім’я володільця даних, строк зберігання й одержувачів.
7. Виконати staging-заявку, перевірити D1, Telegram, адмінку й відновлення.
8. Лише після цього зібрати frontend із
   `NEXT_PUBLIC_TURNSTILE_SITE_KEY="..." npm run build`.

Максимально покроковий порядок: `docs/CLOUDFLARE_SETUP_UA.md` і
`docs/DOMAIN_SETUP_UA.md`.

## Наступний продуктовий етап

Після активації інфраструктури й отримання реальних виробничих даних:

1. замінити демо-товари/зображення на затверджені;
2. внести приватний price book і правила доставки/монтажу;
3. перевірити 5–10 реальних кошторисів із майстром;
4. перейти до першого 2D-конструктора на трьох стартових композиціях;
5. 3D додавати лише після стабільних 2D-правил.

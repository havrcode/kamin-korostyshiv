# Стан проєкту «Камінь Коростишів»

Оновлено: 31 серпня 2026 року.

## Зафіксовані рішення

- Цільова інфраструктура: власний акаунт Cloudflare, спочатку Free.
- Поточний ChatGPT Sites використовується для розробки, перегляду й демонстрації.
- Публічний сайт, API й майбутня адмінка мають працювати в одному Cloudflare-проєкті.
- Основний сайт залишається на React + TypeScript.
- Публічні сторінки збираються статично через Next.js `output: "export"`;
  Vinext/Vite для них більше не використовується.
- Cloudflare Worker оброблятиме лише серверні задачі: заявки, адмінку, розрахунки,
  доступ до D1/R2 та сповіщення. Постійний Node.js-процес не потрібний.
- Адмінка на першому етапі матиме адресу `/admin`, а не окремий піддомен.
- Заявка на прорахунок важливіша за кошик, онлайн-оплату або кабінет клієнта.
- Робочий номер: `+380 66 057 09 87`, поки без імені.
- Остаточну назву, логотип, адресу, графік, реальні фотографії, категорії,
  товари й ціни ще треба узгодити.
- 2D/3D-конструктор збережено як окремий стратегічний напрямок після першого запуску.
- Погоджено автоматичний цикл для перевірених змін: Sites → приватний GitHub
  `main` → повторні GitHub Actions перевірки → новий незмінний тег. Окреме
  підтвердження для тегування завершеної версії не потрібне.

## Що вже зроблено

- Створено адаптивну односторінкову презентацію бізнесу.
- Підготовлено секції: головний екран, категорії, процес, камінь, послуги,
  FAQ, контакти й футер.
- Додано базові SEO-метадані, Open Graph-зображення та favicon.
- Виправлено мобільне слово «Майстерність»: воно зменшується тільки на вузьких
  екранах і не переноситься.
- Номер телефону винесено в єдиний конфіг і підключено до кнопок дзвінка.
- Дані категорій, каменю та FAQ винесено з великого компонента в окремий файл.
- Клік по категорії автоматично передає її у форму й показує, що саме вибрано.
- Форма чесно позначена як попередня: вона не імітує реальне надсилання.
- Додано стримані появи секцій під час прокручування без scroll-jacking.
- Анімації вимикаються для `prefers-reduced-motion`; без JavaScript контент видно.
- Мобільне меню закривається клавішею Escape та блокує прокручування сторінки.
- Створено правила для наступних змін і навчальну документацію.
- Виправлено зсув блоку переваг «Точний проєкт / Виготовлення / Зручне
  замовлення»: центрування більше не конфліктує зі scroll-reveal-анімацією.
- Додано handoff, журнал рішень і changelog для перенесення проєкту в локальний
  Codex без втрати домовленостей.
- Прибрано Vinext, Vite, Cloudflare Vite plugin і шаблонний Worker-рендеринг.
- `next build` тепер генерує статичний сайт у `out/`; Worker залишено як
  майбутній окремий серверний шар, а не спосіб показу звичайної сторінки.
- Додано типізований контракт і серверну валідацію майбутньої заявки:
  український телефон, ім’я, категорія, повідомлення, згода й honeypot.
- Підготовлено D1-схему `leads` і `notification_outbox`, унікальні ключі,
  індекси для черги та першу незмінну Drizzle-міграцію.
- Додано unit-тести валідації та GitHub workflow для автоматичного тегування
  кожної успішно перевіреної версії з `package.json`.
- Реалізовано окремий Worker entrypoint і `POST /api/v1/leads` із межею 16 КіБ,
  content-type перевіркою, idempotency key і безпечними відповідями.
- Додано обов’язковий rate-limit binding із fail-closed поведінкою.
- Реалізовано атомарний D1 batch `lead + notification_outbox`, повтор із тим
  самим номером заявки та обробку конкурентної гонки.
- Додано dry-run збірку Worker і unit-тести HTTP/D1/idempotency/rate limit.

## Чого ще немає

- Увімкненого production endpoint і підключення публічної форми.
- Підключеного D1 binding, застосованої production-міграції й резервного
  копіювання.
- Telegram outbox та повторних спроб надсилання.
- Захищеної адмінки й авторизації.
- Сторінок категорій і карток реальних товарів.
- Завантаження фотографій у R2.
- Закупівельних і клієнтських правил прорахунку.
- Власного Cloudflare-проєкту, production-домену й аналітики.
- Політики конфіденційності та погоджених строків зберігання заявок/фото.

## Найближчий блок роботи

1. Узгодити остаточний текст згоди, строк зберігання персональних даних і
   одержувачів Telegram.
2. Створити власний Cloudflare staging, підключити D1 та rate-limit bindings і
   застосувати готову міграцію без її переписування.
3. Реалізувати атомарний claim outbox-подій і Telegram-відправник із retry.
4. Після staging-перевірки підключити форму до готового API та показувати номер
   лише після успішного D1-збереження.
5. Додати мінімальну `/admin`: список заявок, статус, нотатка, журнал дій.
6. Отримати остаточну назву/логотип, контакти, графік і реальні фото.
7. Підготувати production-домен і резервне відновлення.

- одержувачі Telegram-сповіщень.

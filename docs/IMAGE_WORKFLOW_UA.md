# Робота з фото товарів

## Поточний ощадний спосіб

Для фото з телефона є dependency-free macOS-скрипт:
`scripts/prepare-product-image.mjs`. Він не змінює оригінал, робить crop у
потрібному співвідношенні, зменшує розмір і створює WebP без metadata.

Потрібні системні утиліти:

```bash
brew install webp
```

`sips` вже входить у macOS. Підтримуються PNG, JPG/JPEG, WebP, а також HEIC і
HEIF, які macOS тимчасово конвертує перед обробкою.

Приклад для товару:

```bash
node scripts/prepare-product-image.mjs \
  --input "$HOME/Downloads/vaza.jpg" \
  --output public/products/vases/vaza-new.webp \
  --ratio 3:2 \
  --width 1536 \
  --focus 50,50 \
  --quality 86
```

Поточна геометрія карток і товарних фото — `3:2`. `--focus X,Y` задає, де
залишити crop-вікно: `50,50` центрує його, менше значення по Y піднімає кадр,
більше опускає. Це потрібне, якщо виріб у вихідному фото трохи вище або нижче
центру.

## Як фотографувати телефоном

- По можливості використовувати альбомний кадр `3:2`.
- Тримати виріб у центральній безпечній зоні приблизно 70–80% ширини/висоти.
- Залишати орієнтовно 10–15% вільного простору зверху й знизу та 8–12% з
  боків.
- Не торкатися виробом країв кадру: після crop і responsive-показу край може
  зникнути.
- Камеру тримати прямо відносно виробу, не змінювати форму перспективою й не
  обрізати ніжки, краї, заокруглення або гострі кути.
- Для вертикального фото залишати більше повітря з боків і передавати
  `--focus`, якщо виріб не в геометричному центрі.

Скрипт не вгадує межі предмета та не виправляє невдалу перспективу. Тому
оригінальний PNG/JPG/HEIC треба зберігати окремо в `work/` або пізніше в R2.
WebP можна перегенерувати будь-коли з того самого оригіналу.

## Майбутня адмінка фото

Окремий сервіс або піддомен зараз не потрібні. Рішення для першого production:
залишити `/admin` у цьому проєкті, а pipeline зробити повторно використовуваним
через нейтральний CLI та конфігурацію кожного сайту. Після другого реального
проєкту його можна винести в приватний пакет або окремий CLI.

Для одного товару доцільно мати максимум 5 активних фото: одне головне і до
чотирьох додаткових ракурсів. Адмінка має дозволяти додати, замінити, сховати,
відновити, видалити та змінити порядок фото, але ліміт п’яти повинен перевіряти
Worker, а не тільки інтерфейс.

Production-потік:

1. Адмін завантажує PNG/JPG/HEIC через захищений `/admin`.
2. Worker перевіряє Access/JWT, MIME, сигнатуру файлу, розмір, dimensions і
   кількість активних фото.
3. Оригінал зберігається в приватному R2, а WebP-варіанти генеруються для
   `card` і `detail`.
4. D1 зберігає `product_id`, object keys, порядок, published, dimensions,
   checksum, автора, timestamps і soft-delete.
5. Публічний frontend читає тільки опубліковані варіанти.

Для першого production локальна підготовка WebP є дешевшою й передбачуванішою.
Автоматичну серверну конвертацію краще підключати після появи реальних фото:
через Cloudflare Images/Transformations або окремий image worker, а не тягнути
важкий Node image stack у звичайний Worker.

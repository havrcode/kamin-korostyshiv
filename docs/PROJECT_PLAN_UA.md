# План розробки Kaminchyk

Оновлено: 1 вересня 2026 року.

## 1. Мета продукту

Потік залишається простим: людина знаходить напрямок → відкриває конкретний
виріб → передає його у форму → сервер перевіряє й зберігає заявку → майстер
бачить її та формує перевірений кошторис. Кошик, онлайн-оплата й кабінет
клієнта не затримують запуск.

## 3. Межа релізу v1.0.0

`v1.0.0` є завершеним кодом і public demo. Це свідомо не означає, що без
власника вже існують домен, Cloudflare bindings, юридичні реквізити або реальні
закупівельні ціни. Без них Sites не збирає дані, а каталог показує тільки
позначені концептуальні візуалізації й «після прорахунку».

### Frontend і каталог — виконано

- головна, каталог, 5 категорій, 9 товарів, privacy/admin/404;
- стабільні ID/slug, category/product routes, breadcrumbs, metadata;
- товар автоматично підставляється у форму;
- 9 згенерованих WebP-візуалізацій із чесною позначкою;
- адаптивність, keyboard/reduced-motion, robots і sitemap.

### Заявки й Telegram — код виконано, активація очікує акаунт

- server validation, Turnstile, rate limit, idempotency;
- D1 `lead + outbox` одним batch;
- Telegram claim/retry/lease/Cron;
- demo Sites не передає персональні дані.

### Адмінка — код виконано, активація очікує Access/D1

- `/admin` shell;
- server-side RS256 JWT, Access audience й email allowlist;
- список заявок, статуси й audit log;
- fail-closed без production bindings.

### Кошторис — ядро виконано, ціни очікують бізнес

- приватний версійний price book;
- окремі `InternalEstimate` і `ClientEstimate`;
- public JSON не містить собівартості/націнки;
- пропущена ціна не замінюється вигаданою, а вимагає ручної перевірки.

## 4. Активація production

Це не нова версія коду, а контрольований операційний запуск:

1. акаунт Cloudflare власника + 2FA;
2. домен `.com.ua` на власника;
3. D1 + міграції;
4. Turnstile sitekey/secret;
5. Telegram bot token/chat ID + Cron;
6. Cloudflare Access + admin email;
7. юридичні реквізити, згода й строк зберігання;
8. staging-тест і тільки потім production build із реальною формою.

Інструкції: `docs/CLOUDFLARE_SETUP_UA.md`, `docs/DOMAIN_SETUP_UA.md`.

## 5. Уточнення реальними даними

Коли власник і брат погодять асортимент:

- звірити категорії й назви;
- замінити visuals на реальні фото з правом публікації;
- додати матеріали, розміри, товщини й сумісність;
- погодити передню/задню сторону, кольорові вставки й портрети;
- внести закупівельні ціни, роботи, націнку, доставку й монтаж тільки серверно;
- описати всі причини ручного уточнення;
- прогнати 5–10 історичних/контрольних замовлень через calculator.

## 6. Після v1 — 2D/3D-конструктор

1. Три перевірені пресети: вертикальна на 1 портрет, горизонтальна на 2,
   горизонтальна на 3.
2. 2D front/back, компоненти, камінь, портретні зони й JSON проєкту.
3. Серверний попередній кошторис і обов’язкова ручна перевірка.
4. Безпечний crop/preview фото.
5. Лише потім оптимізовані 3D-моделі з 2D fallback.
6. SaaS/white-label — тільки після доказу користі на власних заявках.

Повна специфікація: `docs/CONSTRUCTOR_2D_3D_PLAN_UA.md`.

## 7. Незмінні правила

- внутрішні ціни, формули й secrets ніколи не входять у public JS/Git;
- без даних показуємо «після прорахунку», а не fallback-ціну;
- згенероване не видаємо за виконану роботу;
- кожна заявка спочатку зберігається, Telegram є сповіщенням;
- кожний release-тег незмінний;
- перед релізом: lint, typecheck, build/test, Worker dry-run і UI wide/mobile.
